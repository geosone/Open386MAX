Standard setup enables MAXTEXT after 386MAX in CONFIG.SYS through 386LOAD.
Expert DOS setup (SETUPDOS /EXPERT) can disable it. SETUP.INF supports
[Setup] Mode=Expert and [386MAX] MaxText=0; the default is MaxText=1.
Windows setup exposes the same checked-by-default option.

Loading without options preserves the current video mode. Choose a boot
mode directly, without an AUTOEXEC.BAT helper:
  DEVICE=C:\386MAX\386LOAD.SYS PROG=C:\386MAX\MAXTEXT.SYS /MODE=80x50

Optional free CP437 8x8 font:
  DEVICE=C:\386MAX\386LOAD.SYS PROG=C:\386MAX\MAXTEXT.SYS /MODE=80x50 /FONT=UNSCII

DEVICEHIGH=C:\386MAX\MAXTEXT.SYS /MODE=80x50 is another route on DOS
with working UMB linkage. Ordinary DEVICE also works without 386MAX.
The tested Enhanced DR-DOS image uses 386LOAD for UMB loading.
Use only one load line. DEVICEHIGH may fall back to conventional memory;
inspect /STATUS. Setup preserves existing MODE/FONT switches on reload.

SYS options: /MODE=COLSxROWS, /FONT=ROM (default), /FONT=UNSCII.
A colon instead of '=' is accepted; case and option order are ignored.
Unknown, duplicate or malformed options reject loading. Boot selection
uses only loader-provided temporary space, checked before writing to it.
Incompressible screen/font data or insufficient space can reject a boot
change safely; no DOS memory allocator is called during initialization.

Commands after boot:
  MAXTEXT /LIST
  MAXTEXT /SELECT
  MAXTEXT /STATUS
  MAXTEXT /MODE:80x25
  MAXTEXT /MODE:80x43
  MAXTEXT /MODE:80x50
  MAXTEXT /MODE:80x60
  MAXTEXT /MODE:132x60
  MAXTEXT /RESTORE
  MAXTEXT /PUSH
  MAXTEXT /POP
  MAXTEXT /HELP

SELECT offers only discovered modes; type a number, or 0/Esc to cancel.
RESTORE returns to boot geometry and clears the screen. PUSH remembers the
current geometry (set by MAXTEXT, MODE or a program) without a change; POP
returns to the last remembered one, e.g. after a program that left 80x25
(still active:  no change). Mode changes also clear the display. Exit codes: 0 success, 1 missing/incompatible driver,
2 unsupported syntax/mode, 3 temporary allocation failure, 4 transaction
failure (the printed API result distinguishes causes).

VGA supports 80x25/43/50. VBE IDs 108h-10Ch cover 80x60 and 132x25/43/50/60,
but appear only after mode-list, text/TTY/layout/window and full-state
checks. Graphics, non-VGA, banked, non-B800h and unsupported modes fail.
Successful VBE calls alone do not prove directly usable text memory.
An identified PCI Cirrus GD5446 also supports native 80x60 with fixed
640x480 timing and saved PLL state. QEMU-tested; physical cards untested.
Native 132-column modes, 100x60, 160x100 and dynamic loading remain future work.

Changes require page zero and a verified text layout outside Windows.
Failures roll back video state, all text pages and all font banks, with
rollback failure reported separately. No graphics text emulation, CON
replacement or guaranteed support for hardcoded 80x25 applications.

Windows 3.11 starts with plain WIN from 80x50 in QEMU/386MAX. Stock VGA and
vbesvga.drv v1.0-beta4 at 800x600x8 were tested, including return to DOS and
another text-mode change. The external VBE VDD replaces a custom font
with the BIOS font on exit; another MAXTEXT mode request reapplies Unscii.
On QEMU Cirrus, WIN also starts from native 80x60, but that VDD returns at
80x50. MAXTEXT /MODE:80x60 restores native geometry and optional Unscii;
there is no automatic Windows-exit hook.
No physical GPU or complete windowed/full-screen DOS-box claim is made.

Unscii font data: Public Domain/CC0, https://github.com/viznut/unscii
Revision 257b4dfeb50651510fe8b9cf4f151a148a4490e4, unscii-8.hex only.
Four missing CP437 symbols are original CC0 Open386MAX additions. Original
source, attribution and reproducible conversion are in MAXTEXT/FONTS.
The optional 8-pixel font applies to 8-pixel modes; other sizes retain the
BIOS font. It is CP437, not a DOS code-page replacement; keep an appropriate
ROM/DOS font for other code pages. Its data costs an extra 2 KiB resident.

Resident usage is approximately 5.2 KiB with the ROM font, including the
private BIOS stack. Runtime clients temporarily allocate 104 KiB for full
screen/font/BIOS backup and free it before exit. Actual size is in STATUS.

Public API 1.2: open MAXTEXT$ with INT 21h/3D02h, check device via 4400h,
then read the 24-byte MXT1 status via 4402h. Check signature/version/size
and the mode bitmap. 4403h takes the 16-byte MXTC command packet; check
carry, count and result. The packet layout remains compatible with 1.1.
MAXTEXT.H/MAXTEXT.INC define fields; MTEXAPI.C demonstrates detection and
supported geometry requests without QUILIB or resident client code.
ASQ records optional status in snapshots; MAX shows an optional status line.
Both tools and QUILIB still work with MAXTEXT absent.
